# JARVIS Mark LI v2.0.0

Released as the annotated Git tag `v2.0.0` on 2026-07-23. The tag resolves to
commit `0f60519d9ecaed5845c48ff19ddbc1b911721871` with the subject
`Prepare repository for public release`.

These notes document the tagged source snapshot. They do not announce a new
GitHub Release, claim that an installer was tested, or extend compatibility
beyond the evidence described below.

## Summary

Mark LI is a major prototype update to the earlier JARVIS adaptation. It adds a
new desktop interface and workspaces, local wake-word activation, persistent
memory, permission-controlled tools, automation, and optional external-service
integrations while preserving attribution to Mark XLVIII.

## Main changes

- Mark LI Core interface, Pet Mode, and specialized Study and GEO workspaces;
- local “Hey Jarvis” activation through OpenWakeWord with configurable Vosk
  fallback;
- Gemini Live voice flow with interruption and audio-recovery behavior;
- persistent user-controlled memory and memory-graph support;
- central tool registry with risk-based permissions and confirmations;
- screen and camera vision plus desktop and file automation;
- optional Obsidian, Google Workspace, Outlook, and phone-dashboard support;
- security, attribution, baseline, and technical documentation for public
  source distribution.

The chronological project history remains in the
[changelog](../../CHANGELOG.md). The previous public version is retained under
the existing `v1.5-legacy` tag, which this phase does not modify.

## Requirements

| Component | Requirement |
| --- | --- |
| Operating system | 64-bit Windows 10 or 11 recommended; CI validates Windows only |
| Python | Python 3.12 recommended; repository documentation supports 3.12–3.14 |
| Hardware | Microphone required for voice; camera optional |
| AI service | Gemini API key and network access |
| Wake word | Bundled OpenWakeWord models; optional Vosk model for custom phrases |

## Installation from the tag

```powershell
git clone https://github.com/alejogaisser/J.A.R.V.I.S.-Prototype.git
cd J.A.R.V.I.S.-Prototype
git checkout v2.0.0
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m playwright install chromium
```

Copy `config\api_keys.example.json` to `config\api_keys.json` and add a
Gemini API key locally. Never commit that file. Optional integrations require
their corresponding example configuration and provider setup from the tagged
README.

## Reproducible validation

For development validation, install `requirements-dev.txt` in place of the
runtime-only requirements and execute:

```powershell
python -m pip install -r requirements-dev.txt
python jarvis_launcher.py --help
python scripts/check_secrets.py --repo-root .
python -m pytest -q
powershell -ExecutionPolicy Bypass -File scripts\validate_baseline.ps1 `
  -Python .\.venv\Scripts\python.exe
git diff --check
```

Report the result of each command exactly. A command that cannot run because of
the environment, dependency installation, hardware, account, network, or
external service remains not verified.

The automated baseline mocks or avoids Gemini sessions, microphones, cameras,
desktop automation, browsers with real effects, external accounts, and the LAN
dashboard. Passing it is not evidence of real hardware compatibility or a
successful external effect.

## Known limitations

- JARVIS Mark LI is a prototype and is not production-ready or safety-critical
  software.
- Windows is the only CI platform. macOS and Linux behavior is partial and not
  claimed as verified compatibility.
- Gemini-backed operations and optional integrations send required request data
  to external providers and depend on their availability, policies, and quotas.
- Visual automation depends on the active desktop, window layout, display
  scaling, and recognition quality; it requires supervision.
- Some optional or inherited paths need dependencies that are not separated
  into reproducible extras.
- Permissions and confirmations reduce risk but do not make unattended
  sensitive automation safe.
